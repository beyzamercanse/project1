RiskLedger

What did the book make today, why, and how close is each counterparty to its limit?

A risk lakehouse for a synthetic power and gas book. Trades arrive as versions (new, amended, cancelled), are marked to market against forward curves every business day, and roll up into P&L explain, historical VaR, stress tests and exposure against credit limits. A reconciliation checks the front-office book against the risk copy, break by break.

Python · pandas · dbt · Databricks · Delta Lake · GitHub Actions

In progress: risk engine, dbt models and tests are done. Next is the full medallion run on Databricks.

GridFlow

Can a desk trust the power prices and weather it pulls from public APIs?

A batch lakehouse for European power-market and weather data. Raw API responses are kept as immutable Bronze JSON with their request metadata, then normalised into Silver Parquet on S3-compatible storage, with every interval in UTC and checked for daylight-saving shifts, interval length and units.

Python · PyArrow · Parquet · S3 (MinIO API) · Docker · Dagster · dbt · DuckDB

In progress: ingestion, Bronze and Silver layers are done and tested. Next are Dagster backfills and dbt Gold marts.

Desk Copilot

What drove today’s P&L on the German power book? Ask it in plain English.

An AI analyst for trading-desk questions. A LangGraph agent decides whether a question needs a defined metric, a governed SQL query over the risk marts or a search over outage notices, and refuses what it can’t answer safely. Generated SQL is parsed and checked before it runs, on a read-only database role.

Python · LangGraph · LLM APIs · PostgreSQL · pgvector · sqlglot · FastAPI

In progress: agent, guardrails and retrieval are done. Next is growing the eval set from 12 to 50 questions, tracking accuracy, latency and cost.

TickStream

How deep is the book right now, and is the feed still alive?

A real-time pipeline for level-2 order books. A WebSocket producer keeps a local book per symbol and streams snapshots through Kafka (Redpanda) into ClickHouse, where materialised views compute spread, depth and order-flow imbalance for Grafana.

Python · WebSockets · Kafka (Redpanda) · ClickHouse · Grafana · Docker

In progress: producer, ClickHouse views and Grafana provisioning are done. Next is an end-to-end run and a latency write-up.

Mobility Pipeline

Can operations trust yesterday’s trip numbers?

A batch pipeline for a feed that resends records, delivers trips late and corrects fares. Each batch is checksum-verified and loaded in one transaction, bad rows are quarantined with a reason, and a restatement audit shows how much each day moved after it was first published.
